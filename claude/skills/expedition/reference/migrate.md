# Migrating an older release folder

Read this when a script refuses a release folder and names a `migrate/` script, or when a release was started under an older form of this skill. Each migration runs once per release. `<skill>` is this skill's directory; the scripts find the release folder as every script does ([files.md](files.md), Scripts).

## Which migration

- Old layout (no `plan/`): `python3 -I <skill>/scripts/migrate/layout.py v0.<n>.x` once; the other scripts refuse the folder until then
- A folder that still has `status/ownership.md`: `python3 -I <skill>/scripts/migrate/epics.py v0.<n>.x [--dry-run]` once (fills every epic file's Ownership table from its specs, removes an empty Notes section, `git rm` of `status/ownership.md`; commits nothing); the other scripts refuse the folder until then
- Epics run before start sprints existed (grid rows, no `Starts:`): `python3 -I <skill>/scripts/sprints/backfill_starts.py v0.<n>.x [--dry-run]` once, then `sprints/check.py` and `sprints/refresh.py`
- A folder that still has free-standing fix trackers (`run/trackers/fix-<slug>-tracker.md`, a tracker and a grid row with no spec, from older releases): `python3 -I <skill>/scripts/migrate/fixes.py v0.<n>.x --dry-run`, check the table, then without `--dry-run`, with `--map <slug>=E<n>:<NN>` for any choice to correct (each fix becomes a follow-up spec in an epic; commits nothing); the other scripts refuse the folder until then
- A `decisions.md` still in the heading format (`## Round` headings, `### D<n>` items, `[E<n>]` and `[Done]` tag lines): `python3 -I <skill>/scripts/migrate/decisions.py v0.<n>.x [--dry-run]` once (the board in place, lanes by the Done rule; prints the cards per lane and the To do and In progress ids; commits nothing); the other scripts refuse the folder until then
- Old queue files (`findings.md` or `run/attentions/`, no `queue.md`), a `queue.md` that is not a kanban board yet, or a board in the old card format (from tags, `Decision:` facts): `python3 -I <skill>/scripts/migrate/queue.py v0.<n>.x [--dry-run]` once; the other scripts refuse the folder until then
- Trackers that still say `merged` or `skipped`, or a waiting milestone whose cell is still `[ ]`: `python3 -I <skill>/scripts/migrate/statuses.py v0.<n>.x [--dry-run]` once (the five statuses of [formats.md](formats.md), Milestone status; commits); no script refuses the folder before

## What the scripts refuse

Older releases (v0.8.x and earlier, and v0.9.x until migrated) keep the flat layout. The scripts do not read them: a folder without `plan/` is refused with one line naming `migrate/layout.py`, which moves it once. A folder still on the old queue files is refused with one line naming `migrate/queue.py`, a `decisions.md` still in the heading format with one line naming `migrate/decisions.py`. A folder that still has `status/ownership.md` is refused with one line naming `migrate/epics.py`.

Releases before this rule had free-standing fix milestones: a `run/trackers/fix-<slug>-tracker.md` and a `fix <name>` grid row, with no spec and no epic. The scripts refuse such a folder until `migrate/fixes.py` has moved each one into a follow-up spec of an epic.

## Scripts

| Script | Does | When |
|---|---|---|
| `python3 -I <skill>/scripts/migrate/layout.py v0.<n>.x` | `git mv` of the flat release folder into the `plan/`, `run/` and `status/` layout above; copies the page template; appends the two `status/` render lines to `.gitignore` when missing; rewrites the plan's spec links and the old paths inside the handoffs and epic files; `git rm` of the old `ownership.md`; runs `migrate/decisions.py` when `decisions.md` is in the heading format, `migrate/queue.py` when `queue.md` is missing, then `migrate/epics.py`; reruns `sprints/check.py`, `sprints/refresh.py`, `status/report.py`; commits nothing; refuses a folder that has `plan/specs/`, merges into a target folder made early (an epic file) | once per release still on the flat layout |
| `python3 -I <skill>/scripts/migrate/epics.py v0.<n>.x [--dry-run]` | fills the Ownership table of every epic file that has none from its specs (one row per decision and citing spec of the epic, Files the files that spec's milestones own, Milestone and Sprint as `epics/table.py` writes them, Sprint from the grid), removes an empty `## Notes` section and keeps a non-empty one, `git rm` of `status/ownership.md`; prints one line per epic file; commits nothing; a second run changes nothing; `--dry-run` writes nothing | once per release that still has `status/ownership.md` |
| `python3 -I <skill>/scripts/sprints/backfill_starts.py v0.<n>.x [--dry-run]` | writes `Starts:` into each epic file whose epic has grid rows and no value (the lowest column among its finished rows, else the current sprint with that epic's own rows ignored), commits nothing, prints the value per epic and every row that moves with its old and new column | once for a release whose epics predate `Starts:` |
| `python3 -I <skill>/scripts/migrate/fixes.py v0.<n>.x [--dry-run] [--map <slug>=E<n>:<NN>]...` | turns every free-standing `run/trackers/fix-<slug>-tracker.md` of an older release into a follow-up spec `NN.M` with one milestone in an epic. Epic and parent spec, first evidence that decides: a spec the tracker names (under `Depends on` or as "spec NN" in its text); else the spec its cited cards or decisions lead to, or the one epic those decisions are tagged with; else the epic with rows in the fix row's sprint column (`unsure`); `--map` sets both for one fix. Writes the spec (title, citations, Epic line, an Acceptance line pointing at the tracker's recorded checks, the milestone block, `Starts:` when the row is not finished), the Deliverables row, the epic file's `Specs:` line and Ownership row, `git mv` of the tracker to `NN.M-<slug>-tracker.md`, the grid row relabelled with its cells kept, the old tracker path and `fix-<slug>` mentions rewritten in `queue.md`, epic files, handoffs, specs and trackers; reruns `sprints/refresh.py` and `sprints/swimlanes.py`; commits nothing. `--dry-run` prints one line per fix (epic, parent, new number, evidence, `unsure`) and writes nothing; a second run changes nothing | once per release that still has fix trackers |
| `python3 -I <skill>/scripts/migrate/decisions.py v0.<n>.x [--dry-run]` | converts a `decisions.md` in the heading format in place into the board: every decision, title and body line kept (blank lines between bullets dropped, every line inside a fence kept), `#E<n>` from the tag line, `#R<n>` from the round heading, the lane from the Done rule, a `[Done]` tag line read as closed by hand; prints the cards per lane, the To do and In progress ids and any line not placed; commits nothing; a second run changes nothing | once per release whose `decisions.md` is in the heading format |
| `python3 -I <skill>/scripts/migrate/queue.py v0.<n>.x [--dry-run]` | converts a board in the old card format (from tags such as `#owner` or `#run-E10`, `Decision: D<n>` facts) in place: from tags removed, each `Decision: D<n>` fact becomes `#D<n>` on its card's title, the Decided cards ticked and tagged `#E<n>` from `decisions.md`, card order, facts and lanes kept, `"tag-action":"kanban"` added to the settings only when absent; prints cards per lane, the Decided cards ready, in an epic and done, the ready card ids with their D ids, and the from tags removed; a second run changes nothing. Converts a `queue.md` in the heading format (`### Q<n>` with its `- Tags:` and `- From:` bullets) to the board in place: ids and order kept, the Tags value picks the lane, From is dropped, the other bullets become tab-indented facts. For a folder that still has `findings.md` or `run/attentions/`: builds the board (F items, then A items, numbered Q1.. in that order, merged duplicates mapped to one card, lanes from the old tags, decision citations and fix trackers), rewrites the old ids and file names across the release folder except `reference/`, `git rm` of `findings.md` and `run/attentions/`, commits nothing; prints the id mapping and every bare F or A token left as `path:line: text`. Both print the cards per lane and any entry not placed; `--dry-run` writes nothing | once per release still on the old queue files, the heading format or the old card format |
| `python3 -I <skill>/scripts/migrate/statuses.py v0.<n>.x [--dry-run]` | in the main checkout's release folder: tracker `Status: merged (...)` to `done (...)`, `skipped (...)` to `stopped (...)`; a `[ ]` cell whose tracker (the copy `status/progress.py` reads, the milestone worktree included) says waiting to `[~]`; then the grid chain when a cell changed, the swimlane data, one commit; prints one line per change; a second run changes nothing; `--dry-run` writes nothing | once per release that has trackers from before the five statuses |
