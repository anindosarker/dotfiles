# Release files

## Layout

```
.ai/plans/v0.<n>.x/<owner>/
├── plan.md                 ← authored: ## Goals, ## Epics
├── epics/NN-<slug>.md      ← authored: one epic; follow-up epics NN.M-<slug>.md; section 2.1 holds one ### Milestone: <name> block per milestone
├── ownership.md            ← generated by ownership.py from the milestone blocks and the fix trackers: | Milestone | Epic | Depends on | Files | and the Critical path line; never edited by hand
├── sprints.md              ← generated by sprints.py from ownership.md and the epics' Batch lines, by the talker on go and the runner on merge: the grid, one row per milestone, one column per batch; ticked by the runner
├── decisions.md            ← accepted decisions, D<n> items under round headings, each with its batch tag line
├── findings.md             ← problems found in the code, F<n> items under round headings
├── process.md              ← this project's facts for the release, about ten P<n> rules, two to five explicit bullets each (branches, milestone branch and worktree, merge, release, checks on the shared machine, agent sandbox, public surface, commits, shared files, plans); copied from the previous release by new_cycle.py, audited and rewritten rule by rule with the owner before the run (SKILL.md Process notes)
├── trackers/NN-<slug>-tracker.md ← one per milestone: status, task lines, check lines, staged attention items; fix-<slug>-tracker.md for a fix milestone
├── attentions/ATTENTION-<YYYY-MM-DD>.md ← A<n> items for the owner, written during the run
├── handoffs/               ← write-handoff output
└── reference/              ← supporting material
```

Releases before 2026-10-31 keep the flat layout (epic files, trackers and ATTENTION files at the root). Releases before 2026-11-06 keep the legacy layout: `<release>-plan.md`, `specs/`, a `## Stories` table and a `| Story` grid. `status.py` reads both, reports them as legacy and never rewrites them.

Formats of each file: [formats.md](formats.md).

## plan.md sections

Exactly two, in order: `## Goals`, `## Epics`. No other `## ` section. Process rules are cited `(P<n>)`, never repeated.

Epics table: columns `#`, `Epic` (linked to the epic file), `Scope`. Scope is one outcome sentence under 120 characters: no file lists, no mechanics; the epic file holds them.

Milestones live in the epic files, not in `plan.md`: each epic's section 2.1 holds one `### Milestone: <name>` block per milestone with the lines `- Files owned: a, b`, `- Depends on: <milestone names or epic numbers, or none>`, `- Review: none | fable`, then `- Task 1: ... Checks: ...` lines. Branch and worktree are assigned at launch and recorded in the milestone's tracker, never in the epic.

`ownership.md` is generated by `ownership.py` from those blocks: a table `| Milestone | Epic | Depends on | Files |` and a line `Critical path: A > B > C`. An edge from A to B exists when B lists A under `Depends on` or when A and B share a file (lower epic number first); a milestone's column is the longest chain ending at it plus one; the critical path is the longest chain, ending at the release milestone. A file shared by two milestones of the same column, or a dependency cycle, is a script error naming the file and the two milestones, fixed in the epic.

Every file the release changes has exactly one milestone owner while it runs. Two milestones that share a file sit in different columns, or the two merge. Shared files no milestone owns (`plan.md` appends, changelog blocks, generated registry and docs copies) follow the release's `process.md`. What two or more milestones need (dependency adds, lockfile, lint or CI config, shared helpers, baseline captures) lands as the first batch's shared milestone.

Checks live in each task's `Checks:` and the release's `process.md`; Acceptance in each epic's `Acceptance:` line (programmatic or judged); the release in the release epic; sandbox rules in `process.md`.

`plan.md` is not frozen: each go appends the batch's epics.

## sprints.md

Beside `plan.md`: a title, an `Updated: <date time>` line, one table `Milestone`, `B1` .. `Bn`. Grid only: one row per `ownership.md` row of a batched epic, its text followed by the D ids the epic cites ([formats.md](formats.md)); fix milestones added mid-run get a row from `new_fix.py`. A release with no epic Batch line keeps the older `S1` .. `Sn` columns. A cell is `[x]` merged, `[ ]` running, `·` not started, `[!]` blocked (the reason stays in the milestone's tracker under `## Attention`). No legend, no prose, nothing under the table.

`sprints.py` writes it on go (the talker, a new batch column with `·`) and on merge (the runner); the runner ticks it at every boundary. A regeneration keeps the ticks. `status.py` flags a `sprints.md` whose rows differ from `ownership.md`.

A fix milestone (no epic of its own) gets a tracker, `trackers/fix-<slug>-tracker.md`, whose first line cites its findings, for example `(F3, F4)`, and a grid row in the running batch column; `new_fix.py` writes both. `status.py` counts those citations.

## Scripts

Run from inside the repo, as `python3 -I <script> <release>`. They never overwrite an authored file.

| Script | Does | When |
|---|---|---|
| `python3 -I <skill>/scripts/new_cycle.py v0.<n>.x [--owner X]` | creates the release folder with the `plan.md` stub (`## Goals`, `## Epics`), `decisions.md` and `findings.md` (from the templates, with a `## Round 1: discussion, <today>` heading), the subfolders, and `process.md` copied from the newest earlier release (else from `templates/process.md`, placeholders to fill) | a new release |
| `python3 -I <skill>/scripts/new_epic.py v0.<n>.x NN <slug> "<Title>" "<scope>"` | creates the `epics/NN-<slug>.md` stub and the first milestone's tracker `trackers/NN-<slug>-tracker.md` (`Status: planned`), adds the row to the `plan.md` Epics table in order | each new epic or follow-up epic |
| `python3 -I <skill>/scripts/new_epic.py v0.<n>.x --batch B<n> <epic numbers or D ids>` | writes `- Batch: B<n>` under each epic's title line (a D id names the epics citing it) and the tag line `[B<n>]` under each decision those epics cite and each named D id; an existing Batch line or tag is kept | on go |
| `python3 -I <skill>/scripts/ownership.py v0.<n>.x` | reads the `### Milestone:` blocks of every epic linked from `plan.md` and every `trackers/fix-<slug>-tracker.md` (a fix milestone: name from its title, optional `Files owned:` and `Depends on:` lines), writes `ownership.md` (milestone, epic, depends on, files, critical path); errors on a shared file inside one column or a dependency cycle, naming the file and the two milestones. `--overlap <epic numbers or D ids>`: check mode, writes nothing, reports files shared with milestones of running batches, exit 1 on a shared file | after each epic is written; `--overlap` before the batch hint and on fork return |
| `python3 -I <skill>/scripts/sprints.py v0.<n>.x` | writes the `sprints.md` grid from `ownership.md` and each epic's `- Batch: B<n>` line, one column per batch, `·` in new cells; existing ticks survive | talker on go, runner on merge |
| `<skill>/scripts/runner.sh start\|list\|stop v0.<n>.x` | `start`: opens window `runner-<release>` in the current tmux session running the runner (opus, bypass, fixed `--session-id`, `templates/runner-settings.json`, brief), records it in `~/.claude/expedition-runners.json`, resumes a dead one with `--resume`, prints the command outside tmux; `list`: entries with busy or idle; `stop`: closes the window, marks the entry stopped | once per release, and to revive a runner |
| `python3 -I <skill>/scripts/new_fix.py v0.<n>.x <slug> "F3, F4"` | creates `trackers/fix-<slug>-tracker.md` citing the findings, adds the grid row in the running batch column | a mid-run fix |
| `python3 -I <skill>/scripts/find_rules.py [repo]` | read-only: prints project planning-rules paths, one per line, nothing if none | |
| `python3 -I <skill>/scripts/status.py v0.<n>.x` | read-only: missing files, a state table per decision and finding, milestones without tracker, `Status:` line or checks, possible open questions, untriaged ATTENTION items, a `plan.md` `## ` section other than Goals and Epics, an Epics Scope cell over 120 characters, `ownership.md` missing or older than an epic, `sprints.md` missing, without a `| Milestone` table, with rows that differ from `ownership.md` (fix trackers are `ownership.md` rows, so a fix row is never a gap) or with a cell other than `[x]`, `[ ]`, `·`, `[!]`; a legacy folder (`<release>-plan.md`, `specs/`, `## Stories`, a `| Story` grid) is read and reported as legacy, never rewritten; the release's `process.md` (missing, placeholders left, undefined `(P<n>)` citations), a batch summary (deciding, batched, running, done per D item), inferred stage. First line names the planning rules in use | any time |

`<skill>` is this skill's directory.

`status.py` checks only the epic files linked from the `plan.md` Epics table. Other `NN-*.md` files are listed as `supporting:` and not checked. A release may mix legacy and new file formats. `status.py` reads both. Fix-milestone trackers cite findings on their first line and count as citing. Decision states: `unplanned` (no epic or tracker cites it), `planned`, `running`, `done` (every citing tracker merged or done), `deferred` (a `Deferred to` bullet), `superseded`, `unknown` (a citing tracker has no `Status:` line). Stage inference reports discuss and run together: discuss when there are no decisions, a deciding item or an untriaged ATTENTION item; run when a batch is batched or running (an untagged release: when a decision is planned or running).

## Template

Precedence, highest first:

1. `--template PATH` on `new_epic.py`.
2. Project planning rules, found by `find_rules.py`: files named like `*plan*guide*.md` or `planning*.md`, and `CLAUDE.md` or `AGENTS.md` lines that mention plan files. `new_epic.py` writes a contract stub and prints each path. The agent then writes the epic by hand in the project's template. The project rules override the bundled guidelines completely: structure, headings, rules, template.
3. Bundled default, only when no project rules are found: [planning-guidelines.md](planning-guidelines.md), template [../templates/epic.md](../templates/epic.md).

The contract applies in all three: citations, the `### Milestone: <name>` blocks, checks per task, no open questions. A project template that lacks one gets it added in that project's style.

## Conventions

- Citations: `(D7)` for a decision, `(F3)` for a finding, `(A2)` for an ATTENTION item, `(P2)` for a process rule, `(v0.4.x D9)` for a decision of another release. `status.py` also reads the older `(decision N)` form.
- `plan.md` lists `#`, `Epic`, `Scope` only. No duration or size column.
- No questions in plan files. They stay in chat until answered.
- No em dashes in any release file.
